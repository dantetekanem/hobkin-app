# First-run setup

## Outcome

The first time the app opens, a story covers the window before the app shows. The window holds empty for a moment, then a world builds itself: the sky comes, by day in the light theme and by night in the dark one, and mountains rise. hobkin comes up from behind them, hops to the middle of the window in four or five hops, and says hello in speech bubbles, as a character in a game talks. It asks what the user is working toward, whose computer this is when that matters, the user's name and, if they want to give it, their email. It installs Pi and the Pi packages its agents use when they are missing, finds an account Pi already reaches or signs in to the OpenAI subscription, and offers to set up the first routines for those goals. It shows everything else it needs on this Mac and how to add what is missing, says where the settings are, and hands over to the app, where a short tour says what each part does. Settings can run the setup and the tour again. Every step works from the keyboard and by mouse.

This replaces the five-step setup of 2026-11-10 (Welcome, What hobkin does, Connect a model, First settings, Ready) on the user's word of 2026-11-13.

On 2026-11-14 the questions half moved to `044-goal-first-setup`, on the user's word: the setup asks what the user is working toward instead of which computer this is, and the first routines come from hobkin's own templates, shown as cards. This spec keeps the told story: the world, the hops, the glass bubbles, sound, Pi, the account, the hand-off and the tour. The lines it retired say so.

## Decisions

- The setup is one layer over the whole window, above the frame and under the app's dialogs. The frame stays mounted behind it, with no keyboard and no pointer while the setup is open (`inert`). The layer is `role="dialog"`, which the frame's key map (`ui/src/app/key-map.ts`) already leaves alone, so the frame's keys never change screens behind it.
- It opens by itself on the first run. The mark lives in the app's own storage (`hobkin-client-setup`) and is written when the setup ends. Skipped, or told to the end with an account, it is `seen`. Told to the end with no account it is `unfinished:personal` or `unfinished:work` (`unfinished` when the computer was not said), and so is a setup that ends in any way, skipped too, while Pi itself is missing or older than hobkin runs on (since 2026-11-26, the Pi decision below): the next launch opens the setup again at the subscription bubble, so Pi comes next when it is missing and then the account, keeping whose computer it is, and the tour starts only for a setup that is seen. `?setup=1` in the address opens it whatever was saved, so a browser tab can show it. Run setup again, in Settings, opens it from its start.
- The opening, in order: the window's own background for 1.4 seconds (0.45 when run again), so nothing starts the instant the app does; the sky comes, with the sun rising in light, or the moon rising and the stars coming out one after another in dark; a short rest; the mountains rise from below the window, the far ridge first, then the hill in front; and as the last ridge settles hobkin rises behind the last ridge of mountains, on the right, until its eyes show, looks around, and hops to the middle: five hops in a window at least 1100 wide and four in a narrower one. It never lands on a mountain: the first hop takes it over the ridge and down behind the hill, which hides its foot, and every hop after that lands on the hill itself, which is the ground, each one bigger than the last. On its seat it stands a little into the hill, with its shadow under it, so it never looks like it floats. The land is `World.tsx`, and where hobkin hides, hops and stands is `world-geometry.ts`, pure and tested.
- The opening always plays through. A key or a click before hobkin has landed does nothing (the user's word of 2026-11-13, after seeing a click cut the hops short).
- The story is beats, and a beat is one or more speech bubbles above hobkin's head (`story.ts`). A bubble's words arrive one after another. Enter, Space, Right or a click anywhere goes on: first to the whole bubble, when its words are still arriving, then to the next one. Escape or Left goes one bubble back, then to the beat before. A beat's question comes with its last bubble and holds the story until it is answered. Back never passes an install or a sign-in that was done.
- Skip setup, in the top corner, shows only once Pi is installed at the version hobkin runs on and a model account answers: one Pi already reaches, one signed in to in the setup, or a launcher that was kept (`skipShows` in `story.ts`). Missing packages can wait. Until then nothing skips the setup: there is no button, no key ends it, and the story's own skip does nothing. A window with no host never knows Pi is there, so it shows no Skip setup. This is the user's word of 2026-11-26: "\"Skip Setup\" is not an option, honestly ... otherwise wont even work, you can show that after sub/pi is connected ... the rest? no".

- hobkin's own Node. The app carries a Node binary for its host but no npm (`scripts/package/stage.ts`), and npm installs Pi. So on a Mac without npm a live host installs the official build of its own Node version for the Mac's chip, `https://nodejs.org/dist/v<version>/node-v<version>-darwin-<arm64|x64>.tar.gz`, into `client/node` in hobkin's home (`host/src/pi/node.ts`). Its SHA-256 is checked against `SHASUMS256.txt` in the same folder before anything is unpacked. `/usr/bin/tar` unpacks it beside its place, and it is then moved in, so a failure leaves nothing half-made and a second install replaces the first. It needs no admin password and changes nothing else on the Mac. Its `bin` folder goes on the host's own PATH, after the folders there and before the carried Node's, which stays last, and it is one of the places hobkin looks for programs, so npm, the Pi that npm installs and everything the host starts find them at once. A live host puts it on its PATH again at each start. A failure says what failed in plain words (no network, the checksum, the unpack), with anything shaped like a secret hidden. Decided on 2026-11-14: hobkin keeps a copy of its own, so no admin password is asked.
- Look again. The app asks the user's login shell for its PATH once per run (`src-tauri/src/login_path.rs`), and a host restart gets that same PATH, so a Node or Pi installed while the app was open, in a folder such as a version manager's, stayed unfound until the app was quit. When `setup.pi` finds no Pi or no npm, the host asks the login shell again the same way (`host/src/pi/login-path.ts`: `$SHELL`, or `/bin/zsh`, with `-ilc`, the PATH printed between markers, stdin closed, stderr ignored, at most five seconds), adds the folders its own PATH lacks, in their order, each once, with the carried Node's folder last, and looks again. With Pi and npm found no shell is asked, and only a live host asks, so a test never runs a real shell. Look again shows after a failure and when Pi has to be installed by hand. The setup offers no restart: `host.restart` starts a host on the PATH the app asked for at its start, so it finds nothing Look again does not, and it stops running agents and reviews.
